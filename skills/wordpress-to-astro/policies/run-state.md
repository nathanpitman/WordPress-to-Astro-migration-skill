# Run state, configuration and resuming

A migration spans many sessions and long contexts. Keep two small files on disk so any session can resume exactly where the last one stopped, and so tooling does not depend on what the conversation remembers.

## `wordpress-to-astro.config.json` (project root)

Written in Stage 1 from the intake answers and the baseline; read by every script. Hand-maintained: scripts never overwrite it.

```json
{
  "origin": "https://example.com",
  "gates": "stage",
  "options": { "submitForms": false },
  "crawl": { "delaySeconds": 0.6, "concurrency": 1, "userAgent": "wordpress-to-astro (Claude Code; run by <user>; crawling example.com)" },
  "hostingLayers": [ { "name": "wp-rocket", "detect": "data-rocket-", "reversal": "lazy-img, attrs, scripts, comments" } ],
  "volatileTokens": [ "livewire-snapshot", "gravityforms-state", "wp-nonce" ],

  "approvedArtefacts": [ "themed-404", "site-search-script" ],
  "scale": { "pages": 0, "sample": false }
}
```

## `docs/run-state.json`

Updated at every gate (and whenever a step finishes). Generated by you or a script; never edited by hand except to correct it.

```json
{
  "domain": "example.com",
  "skillVersion": "1.0.0",
  "stage": 3,
  "stages": { "1": "done", "2": "done", "3": "in-progress", "4": "pending", "5": "pending" },
  "phases": { "0": "done", "1": "done", "2": "done", "3": "done", "4": "done", "5": "done", "6": "in-progress" },
  "crawledAt": "2026-10-03T09:30:00+01:00",
  "phaseRuns": { "1": { "ranWith": "1.0.0", "ranAt": "2026-10-03T10:12:00+01:00", "lastScriptRun": { "version": "1.0.0", "at": "2026-10-03T10:11:00+01:00" } } },
  "decisions": [ { "id": "host", "question": "Which host?", "answer": null, "status": "open", "default": "neutral JSON", "stage": 1 } ],
  "counts": { "pagesCrawled": 324, "pagesBuilt": 326, "pagesDiffering": 0 },
  "lastCheckpoint": "2026-10-03T14:37:00+01:00",
  "notes": "free text, one line"
}
```

`ranWith`/`ranAt` are set only when a phase is **complete** (at its gate), never by a script finishing: scripts record `lastScriptRun`, because the report that goes with them may still be unwritten. With the reference scripts, `python scripts/stamp.py complete <phases>` does it, `stamp.py crawled` records `crawledAt` (the crawler already does), and `stamp.py status` shows stale phases and locally edited files.

## Resuming

On invocation, before the introduction:

1. If `docs/run-state.json` exists, read it and the config. Tell the user in two or three lines which stage the run is in, which phases are done, which decisions are open, and offer to **resume** (default) or **start over**. Never repeat completed work unless asked.
2. Check the crawl cache and the project still match the state (cache present, project builds). If something is missing, say so before continuing.
3. Re-read the policies and the files for the stage you are resuming; do not rely on memory of them.
4. Continue from the first incomplete step; do not re-run the intake unless the config is missing or the user asks.

5. If `skillVersion` is missing or differs from the skill's current `version`, follow `policies/updating-a-run.md` before offering resume: phases may be `stale`. A phase status of `stale` means done under an older version and due a re-run; resuming without updating leaves it as is.

If no state file exists, this is a new run: start with the introduction.
