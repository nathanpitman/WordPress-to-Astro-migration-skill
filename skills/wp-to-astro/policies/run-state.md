# Run state, configuration and resuming

A migration spans many sessions and long contexts. Keep two small files on disk so any session can resume exactly where the last one stopped, and so tooling does not depend on what the conversation remembers.

## `wp-to-astro.config.json` (project root)

Written in Stage 1 from the intake answers and the baseline; read by every script. Hand-maintained: scripts never overwrite it.

## `docs/run-state.json`

Updated at every gate (and whenever a step finishes). Generated by you or a script; never edited by hand except to correct it.

## Resuming

On invocation, before the introduction:

1. If `docs/run-state.json` exists, read it and the config. Tell the user in two or three lines which stage the run is in, which phases are done, which decisions are open, and offer to **resume** (default) or **start over**. Never repeat completed work unless asked.
2. Check the crawl cache and the project still match the state (cache present, project builds). If something is missing, say so before continuing.
3. Re-read the policies and the files for the stage you are resuming; do not rely on memory of them.
4. Continue from the first incomplete step; do not re-run the intake unless the config is missing or the user asks.

If no state file exists, this is a new run: start with the introduction.
