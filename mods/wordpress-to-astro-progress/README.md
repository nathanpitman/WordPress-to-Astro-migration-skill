# wordpress-to-astro-progress

An optional [Claude Code mod](https://claude.com/blog/claude-code-mods): a band above the prompt that shows where a `wordpress-to-astro` run is, at a glance. The skill works the same without it.

```
wordpress-to-astro · example.com · ██████████░░░░░░░░░░ 7/13 phases   2 open decisions   [Hide]
✓ 1 Discover  ›  ✓ 2 Analyse  ›  ● 3 Build  ›  ○ 4 Verify  ›  ○ 5 Finish
Stage 3 phases:  ✓ Layouts   ✓ CSS   ● Assets   ○ Listings
```

- **Row 1:** the domain, a bar of finished phases out of 13, and the number of open decisions.
- **Row 2:** the five stages. `✓` done, `●` current or in progress, `↻` stale (done under an older skill version, due a re-run), `○` not started.
- **Row 3:** the phases that make up the current stage, with the same marks.
- **Hide** collapses it to a one-line button that brings it back.

## What it reads

Only `docs/run-state.json` in the session's working directory, the file the skill already keeps current at every gate (`policies/run-state.md`): `domain`, `stage`, `stages`, `phases` and the `status` of each entry in `decisions`. It writes nothing, makes no network calls and keeps its own state only for the session. It re-reads the file when a session starts, at the end of every turn, and every 5 seconds (the skill's scripts write it from the shell, outside the conversation).

The band appears when the skill is invoked (`/wordpress-to-astro`, or `/wp-to-astro` for older copies; even before any run exists, when it says "waiting for intake"), or whenever the working directory has a `docs/run-state.json`. Otherwise it stays out of the way.

## Use it

Load it for a session by pointing Claude Code at the folder:

```bash
claude --plugin-dir /path/to/WordPress-to-Astro-migration-skill/mods/wordpress-to-astro-progress
```

(`CLAUDE_CODE_PLUGIN_DIRS` does the same for several folders.) To check it first: `claude plugin validate mods/wordpress-to-astro-progress`.

## Status and limits

- Written against Claude Code **2.1.286**; `claude plugin validate` passes there. An older Claude Code (2.1.226 was tried) rejected the mod's hooks format in `claude plugin validate`, so update first.
- It draws in the `AbovePrompt` slot. It was developed in the desktop app's Code tab; other surfaces (terminal, VS Code) are not tested.
- Phase labels and the stage-to-phase grouping are the skill's own (`stages/*.md`). If the skill's phases change, update `STAGES` and `COUNTED` at the top of `hooks/register.tsx`.
- Any free-text status in `run-state.json` is reduced to four: contains "stale" is stale, "progress" is in progress, "done" is done, anything else is not started.
